# Engine-side directory browser plan

## Approved scope

Default to an **in-app engine-side directory browser on every client**: Windows Tauri, browser and mobile WebView. Keep manual absolute-path registration. Native picking is a secondary, explicitly invoked action, advertised only by engine capability. Never infer filesystem location or picker support from client OS, hostname, localhost or Tauri context. Browsing uses the engine user's OS permissions; it is not a sandbox or a client-filesystem picker.

Existing directories only. No mkdir, clone, uploads, file-content reads, harness/provider setup, ai-jail, hosting move, auth changes, deployment, SSH, restarts, project/session creation during delivery, commits or pushes. The VPS's nonroot `klm` account does not authorize operations against that deployment.

## Backend contract and implementation

Use two small authenticated read handlers (suggested new `engine/directory_browser.go`), with platform helpers only where necessary. No persistence, app-wide filesystem cache, shell listing command, recursive traversal or project requirement.

1. **`GET /api/filesystem/roots`** → `{roots: [{name, path}], home: string|null, nativePicker: boolean}`.
   - Windows: enumerate actual logical drive bits through `golang.org/x/sys/windows.GetLogicalDrives` in `directory_browser_windows.go`. Return absolute drive roots, not a synthetic POSIX `/` or a guessed `C:`. Do not probe every drive while enumerating: removable/offline drives may fail when opened. Home comes from engine `os.UserHomeDir`, validated as absolute. UNC paths remain manually navigable; no network-share discovery.
   - Linux/other Unix: `/` plus engine-user home shortcut; mounted filesystems are reachable beneath `/`. Use a `!windows` helper. Never use browser paths, engine working directory or a guessed `/home/klm`.
   - `nativePicker` means the engine implementation is available (Windows), not a promise of an interactive desktop. Existing native failures remain recoverable. Missing/unreadable home must not prevent Roots from working.
2. **`GET /api/filesystem/directories?path=<URL-encoded absolute path>`** → `{path, parent: string|null, directories: [{name, path}], incomplete: boolean, skipped: number}`.
   - Engine cleans paths using `filepath`; require nonempty absolute, valid UTF-8, no NUL, at most 16 KiB input. No implicit `~`, environment expansion or relative/drive-relative Windows paths. Return cleaned lexical paths; frontend never concatenates separators or computes parents. Root has `parent: null`; UNC share roots must not navigate above the share.
   - Stat/open only an existing directory; enumerate immediate directory children, including hidden directories. No file contents or ordinary-file inventory. Sort returned directories by name deterministically. Return 400 for invalid/not-directory, 404 for vanished/missing, 403 for permission denied, and a recoverable generic error for other I/O failures. Do not turn a failed/partial read into a successful empty listing.
   - Follow directory symlinks/junctions through ordinary OS resolution, retaining the lexical alias in returned/selected paths, matching registration's existing noncanonical identity rules. Inspect symlink/reparse/unknown entry types as needed; never recurse. Broken, inaccessible or unrepresentable entries are omitted with `skipped` and `incomplete`, not silently renamed or claimed absent. Listed directories can still fail on navigation; show that error. No privilege escalation, sandbox claim or write-access prerequisite.
   - Bound work with `os.File.ReadDir` batches (e.g. 128), **10,000 raw entries inspected**, **1,000 directories returned**, and **256 KiB encoded JSON** including escaping/metadata. Do not call unbounded `os.ReadDir` then slice. Use `incomplete: true` whenever a scan/item/byte cap or skipped entry prevents complete coverage. A retained subset may be sorted, but must not be described as the globally first alphabetical results. No cursor/cache/pagination framework is needed: manual path navigation handles omitted children.
   - Close directory handles, check request context between batches and metadata lookups, and keep filesystem I/O outside `app.mu`. Native filesystem calls can block on unavailable mounts; cancellation checks do not guarantee interruption of a blocking syscall. Do not introduce leaking timeout goroutines to simulate that guarantee.

Register both routes through existing `clientAuth.protect`, origin/TLS/CSRF and no-store handling, including SQLite route availability. Do not add auth exemptions or broaden CORS/private loopback bridges. Client helpers must use `request` → `clientFetch`, URL-encode paths and pass abort signals. No raw `fetch`, alternative host resolution or new dependencies.

## UI and state flow

Keep the registration form's name/icon/manual **Project directory** input. **Browse directories** opens the in-app browser on every client; never open native UI automatically. Implement a small project-feature `DirectoryBrowser` component, not filesystem behavior in generic primitives.

- Prefer a browser **view inside the existing dialog**, replacing the form body temporarily, rather than stacking dialogs or nesting forms. Keep name/icon/path drafts mounted in parent state. Browser heading: **Choose directory**; compact context: **Engine filesystem**. Current path input + **Go**, **Home**, **Roots**, **Up**, a scrollable directory-button list, and footer **Cancel** / **Select this directory**. A directory row opens it; only the explicit footer action selects the loaded current directory.
- Load roots/home when browsing opens. Initial target is a nonblank registration path, otherwise home, otherwise Roots. Invalid/unreadable initial paths retain the attempted path/error and navigation controls; no silent substitution. Roots is a navigation view, never a selectable directory. On successful selection, return the absolute path to the registration input and fill the project name from the selected basename only when name is blank. Browsing/selecting alone never registers a project.
- Keep path draft separate from successfully loaded path. Disable Select during navigation, after a failed navigation, or while the path field has unsubmitted edits. An incomplete but successfully opened directory remains selectable. Show **No subdirectories** only for a complete empty listing; otherwise show **Directory list is incomplete. Enter a path to open another directory.** Include skipped-entry information when relevant. Retry repeats the failed target; Home/Roots/Up/manual Go remain recovery routes.
- When engine capability allows, show secondary **Native picker on engine**. Only its click calls existing `pickDirectory`; cancellation retains drafts. Success selects that returned engine path. Disable conflicting browser selection/navigation while native picking is active and offer **Cancel selection**. Guard its result exactly like HTTP listings. Linux/headless browsing never depends on native picker success.
- Own request controllers and a monotonically increasing generation in the feature. Abort/invalidate on new navigation, retry, native invocation, browser cancel, dialog close/unmount and reopen. Apply success/error/**finally** state updates only to the current generation/controller. A slow prior listing/native result must not overwrite a newer path or a cancelled selection. Normal navigation/selection runs in event handlers; effects initialize/clean up only. No speculative data library, memoization or global browser state.
- Cancel/Escape from browser returns to the registration form unchanged; a subsequent Escape closes registration. Stop browser cancellation propagating to the parent close handler. Restore focus to Browse directories; restore opener focus when registration closes. Focus the path on browser entry and a stable heading/path control after navigation; Tab, Enter/Space, Go and Escape must suffice without custom tree keyboard rules. Enter in path navigates, never submits registration. Use semantic buttons/list, labels, visible focus, `aria-busy`, status announcements and alert errors.
- Preserve dialog/backdrop/radii/type/spacing/semantic tokens and existing buttons/icons. Scope new CSS to the feature. Fit narrow mobile and landscape with wrapping controls, usable touch targets, long-name/path wrapping or ellipsis with accessible full text, bounded list scrolling and reachable actions; avoid horizontal viewport overflow. Light/dark and reduced-motion behavior inherit current tokens. Edit-project directory immutability and icon picking stay unchanged. No Flutter or Tauri changes are expected.
